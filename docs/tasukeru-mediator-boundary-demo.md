# Tasukeru 調停役の独立検証デモ

これは手動起動・レポート専用の追加実験です。既存の解析、Observer、調停・確認実験、判定条件を変更しません。
実AI API、実ユーザー承認、台帳への書き込み、自動修復、最終採用は接続していません。

## 何が不足していたか

既存の証拠検証ゲートは、提案の事実・出所が入力記録と一致するかを確認する役割です。
その `REVIEWABLE_DRAFT` は実行許可ではありません。証拠照合だけでは、元の目的が適切か、調停後に対象や権限が変わっていないか、
個別の操作を組み合わせた結果が許容されるかまで検証したことにはなりません。
今回の不足は、この外側の条件を現在の部品と組み合わせて試す独立デモがなかったことです。
既存ゲートの契約内の不具合や、権限回避を確認したという意味ではありません。

## 追加機能

| 確認する境界 | 追加した模擬検証 |
| --- | --- |
| 元の目的・対象・範囲 | 調停後の提案を固定した目的、対象、範囲、報告先と照合 |
| 出所・内容の結び付け | 入力とホスト側の模擬状態をハッシュで結び付け、変更を拒否 |
| 権限の分離 | 自然言語の「安全」「承認済み」は非信頼テキスト。実行権限に変換しない |
| 操作の組み合わせ | 模擬履歴を含めて禁止組合せ・累積予算を確認 |
| 不明・停止・却下 | 不明を安全扱いにせず、与えられた模擬状態の停止・却下を維持 |
| 人間への説明 | 元の依頼、変更後の案、観測事実、未解決情報を分けて表示 |
| 既存部品の保持 | 現在の16ファイルを固定し、変更された場合はデモを停止 |

32シナリオを、調停前後とも同じ独立ルールで検証します。3つの手書きの模擬案では、
最終認証への拡張、対象の変更、禁止組合せを狭めて人間のレビュー待ちへ戻します。
これは模擬案の修正であり、元の解析ログの修復ではありません。どの結果でも実行は許可しません。

## 起動方法

ユーザーがPRを確認して手動マージした後、Actionsの
**Tasukeru Mediator Boundary Demo (fixtures only)** で `main` を選んで手動起動します。
今回のPR作成ではマージ・手動起動を行いません。
標準Linuxランナー、Python標準ライブラリ、合成データだけを使います。
新しいAPIキー、AI課金、Observer取得API呼び出しは不要です。GitHub自体の利用枠・料金はアカウント設定に依存します。

出力は `tasukeru-mediator-boundary-demo-report`。独立テスト記録と、
`demo/report.json`、`demo/baseline.json`、`demo/summary.md` を7日間保存します。
既存の実ログZIPや生の承認情報は、このPRにも初回実行の成果物にも含めません。

ローカル確認：

```bash
python -I -B tests/test_tasukeru_mediator_boundary_demo.py
python -I -B scripts/tasukeru_mediation_demo/run_mediator_boundary_demo.py --output /tmp/tasukeru-boundary-new-report
```

出力先は未作成の場所を指定してください。既存出力は上書きしません。
任意のローカルJSONパケットを `--packet PATH` で渡せますが、64 KB以内に限定され、
`LOCAL_PACKET_UNAUTHENTICATED` と表示します。出所の実認証やObserverの取得経路の検証は行いません。
このオプションはGitHubの起動画面には接続していません。

## 未検証点・限界

- 目的は固定した型・列挙値で確認します。任意の自然言語に隠れた意図を見抜く性能は未検証です。
- 調停案の修正は手書きのテストデータです。実AIが自力で安全な修正を行えることは証明しません。
- 出所、承認者、時刻、履歴、停止状態は模擬入力です。ハッシュ一致は本人確認や記録の真実性を保証しません。
- 実承認、永続的な共有台帳、層間イベントバス、実際の外部操作・サンドボックスは未接続です。
- 別実行をまたいだ停止・二重実行防止は、このデモだけでは検証できません。
- 部品とシナリオのPASSは、システム全体の安全性や本番導入の承認ではありません。

既存ファイルの固定値は `4cc1e5e0a0575ad26879a2bd98639543648314c1` に基づきます。
将来の既存コード更新で固定値が不一致になった場合、内容を別途レビューするまで停止します。
PASSを維持するために、無条件で固定値や停止条件を更新しないでください。

## 設計の背景

調停役は整理・比較・提案を行う役割であり、それ自体を安全境界や承認者にはしません。
文献調査から採ったのは、目的・権限・出所・合成結果を独立した境界で再確認する設計上の着想です。
このデモは論文の実AI実験の再現でも、論文の性能数値の検証でもありません。
